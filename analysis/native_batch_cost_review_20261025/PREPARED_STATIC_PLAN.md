# Minimal prepared-static-snapshot design — review before implementation

Scope: four existing files, no new IR, no global ID memo, no trust flags, no budget change and no raw retry. The three native owners remain stopped until root finishes checkpoint. Fourth file requires explicit authorization: `scar/ir/execution/validation.py`. Without a narrow validator extension `_analyze` necessarily revalidates/encodes the global program each shard; monkeypatching its codec or bypassing generic validation is unacceptable.

1. In execution/validation.py, a sealed runtime-only prepared-snapshot object and a factory call the existing canonical program codec/graph validation once. The object retains exact canonical immutable bytes, SHA/size/schema/version and the exact ProgramGraph after proving its transitive typed records/tuples/enums/scalars are immutable; mutable children cannot take this fast path. No serialized token, supplied `verified=True`, graph-ID cache, arbitrary bytes or caller-supplied index is accepted. An optional typed prepared-snapshot parameter to validate verifies the real token, exact retained program and requested Snapshot. Normal validate callers retain their existing full validation. This token establishes only static program validity/bytes; it grants no native occurrence/source/B/C qualification.

2. In native_port_protocol.py, construct one private prepared static catalog from that token plus the actual owned capture's canonical source identity (Run/process, provider revision, nonce/native namespace, exact raw artifact receipts) and complete original definition-catalog bytes. Independently reconstruct and check the shared ABI once, then build binding indexes by `(provider, region, target)` and validated layouts. Bind the catalog to the exact prepared program/canonical definition bytes; no cross-Run sharing. Each shard still independently replays its actual raw interfaces and calls the dynamic checker for every activation and port, checking INVOKE and normal Return exact original producer/evidence artifact/ordinal, full binding inventory, every actual ValueOccurrence/Use/basis/source/Run/process, known B versus Unknown and exact one denotation. B-empty, zero-Tensor and Unknown paths have no exemption. B/C never enter the static key.

3. `_make_evidence` keeps its old API/default full independent construction. The batch-only private prepared path can reuse the source-bound static token for the exact retained program. If a fresh/changed candidate program is supplied, do full canonical preparation and static ABI checking against the same original source catalog; a new same-Run resealed wrong-order candidate must still reach NativePortOrderError. Do not reject such a fresh constructor solely because it differs from an older scope hash. `require_scope` retains exact model/Run seals and dynamic occurrence checks. Pure `_native_port_order_errors` with existing arguments still performs its full independent check for the14 essential negatives. The prepared branch reuses only proved static work, never a previously accepted model result.

4. In native_protocol.py, `_build_execution` uses the prepared validated Snapshot's schema version instead of serializing the program to retrieve a number. Build per-model maps from activation→INVOKE/Return and operation→evidence bindings once; the resolver uses those exact verified maps after scope validation, replacing repeated list scans. V1 retains its original branch/default and closed domain/16 bound.

5. In native_capture_batch.py, prepare the static program/catalog once after full source discovery and share that same capability across execution shards. Pass it to the ordinary generic validator through the new narrow parameter. Keep source acquisition, coordinate bind, parent closure, source provenance, per-shard projections, budgets and independent final negatives intact. No ownership can be restored from persisted SQLite, report or codec data. The prepared token disappears with the new acquisition process.
