2026-10-27 更新。**进行中，尚未完成。** 本阶段只完成建模和建图；之后先向用户讲解交付，再进入化简。LeWM 是外部测试程序，所有分析规则保持通用。

## 四项功能与完成条件

| 顺序 | 核心功能 | 必须实现 | 自行验收 |
|---|---|---|---|
| 1 | 自动拆解 | 从入口与依赖源码恢复模块初始化、函数/闭包、表达式、调用、分支/循环、异常和读写；动态证据补充实际目标。 | 实际涉及的源码结构有内部图，不以 AST 外壳或调用名称代替。未执行路径仍保留静态结构。 |
| 2 | 自动连接 | 实参/形参、返回值、全局/捕获状态；Torch 有序端口、值与对象/storage/view；IO、资源、异步工作和必要顺序。 | 能沿原端点连续查询依赖。调用嵌套、引用相同和内容不变分别表达，不互相替代。 |
| 3 | 轻量建存 | 函数/Region 独立片段，共享定义与源码上下文，以限定 ID 跨片引用，按需展开和索引。 | 局部查询不载入整个程序；不复制 Tensor 数值或整份执行图；记录实际构建/存取成本。 |
| 4 | 全流程集成 | 通用入口贯通加载模型/数据、CPU 处理、搬运、推理/规划、环境交互、渲染/编码和保存。 | 同一运行的必要输入、状态、结果、资源及完成关系可连续查询。缺边仍算未完成。 |

基础实体为 **Operation、Value、StateLocation、Region、Resource**，分别表示操作、定义结果/引用/状态版本、可变位置、带边界的子图、执行或承载资源。操作行为用多标签细分；输入/输出是端口角色。具体类型、身份和关系以 [PROGRAM_TYPES.md](PROGRAM_TYPES.md)、[WHOLE_PROGRAM_MODEL.md](WHOLE_PROGRAM_MODEL.md) 为准。

## 采集、异步建图与并行

运行时 hook 不应执行 AST lowering、全图构建或优化搜索。当前这些工作已在离线分析侧；但 hook 仍同步提取调用元数据、编码记录，且首次遇到源码时同步归档。因此“图在离线构建”不等于“采集已经低干扰”，后台运行也不等于并行。

目标是三个独立阶段：**必要事实快照 → 有界证据分片 → 异步图构建与跨片连接**。异步队列只能传不可变的元数据和已拷贝的字节，不能把 frame/Tensor/应用对象留给后台线程再读，否则观察时刻和对象生命周期都会改变。线程适合批量 IO；受 GIL 限制的 Python 解析、lowering 和验证适合独立进程按源码/Region 分片。每个分片保留自身顺序与限定 ID，连接器只汇合跨片引用，不把所有图集中复制一遍。预算耗尽、丢记录和未完成分片必须显式报告。

已测成本：上述 201 项正常 source reader 用时 4,709.45 秒，source invocation binder 用时 2,752.00 秒，总计 7,470.32 秒；进程累计读取约 8.57 GB，物理读盘计数为 0。这是分析成本，不能计作 LeWM 性能。尚无并行加速实测，不能据线程数承诺速度。目前先消除跨层连接必须重读整个发布根的接口耦合，再对独立分片增加有界 worker；不把整个共享 graph 或活动 proof owner 直接扔进线程池。

闭合 source-port 分片的依赖构建已实现 spawn 进程池：4 个独立 PID 完成 15 片、2,077 项查询，父进程不加载全图，约 32.08 秒；没有同任务串行 A/B，不声称加速。派生 view 输出 18.6MB，expanded JSON 有重复引用；原核心函数图仍共享引用。采集关闭后的压缩/回读也已实现有界线程并行。

其他并行边界仍需实施：source entry 同 file 多 body 共用 context，native 用闭合 shard 作任务。严格 trace reader 仍主要串行；将来只能并行有界 JSON/typed batch，按原 PID/index 顺序折叠 stack、pending、epoch、预算和错误。不能按 worker 完成顺序拼接或把活动 owner/SQLite 连接送入子进程充当验证。运行中的异步分片图构建尚未实现。

原 `process-ports` 采集于 3,601.876 秒失败退出（上限 3,600 秒，exit241），LeWM 未改、episode 未完成。约 8.03GB 已由 4 个归档线程无损压为 677MB，回读 SHA 后才清理重复原件，失败状态保留。`trace=all` 放大了采集器日志与 getpid 等调用，观测约 8,270 万次 voluntary context switches；未测各因素占比。环境日志批写使 1,000 行对应 write 从 1,001 次降至 5 次；静态 CALL/参数布局缓存移除了逐 CALL 反汇编/整描述构造，动态 defaults/code/receiver 仍逐次观察，字节一致微检查通过。OS 新显式接口范围请求 seccomp-bpf 并保留原 identity/argv/coverage 核验；provider/归档路径已验证，下一次真实 LeWM 才验证组合后的全程采集，不能预称收益。

前端恢复、依赖接线和分片查询可以按不重叠源码并行。运行中的任务使用固定源码；失败保留，不因已有产物而改写退出状态。每个功能用一条真实正常路径验证，具体缺陷才增加最小检查；不扩展测试矩阵、重复 episode 或繁琐 gate。

## 展开边界

软件从入口深入 Python/依赖库、Torch module/operator，直到 runtime launch/copy/allocation/wait 与 GPU kernel/copy/memset。硬件保留程序实际使用的 CPU/GPU、内存/allocation、线程/进程、queue/event、文件与存储及必要属性；NVMe/SSD 类型以证据判定。

原外部243项只是一个实际调用窗口，不能代替全部LeWM源码、路径与资源的覆盖分母。

完整 Linux FD 表、driver/allocator 内部算法、指令和微架构不默认展开。程序侧 IO 身份、内容/range、读写、失败和完成依赖仍保留。见 [MODELING_SCOPE_AUDIT.md](MODELING_SCOPE_AUDIT.md)。

第一阶段仍 **OPEN**，不增加 detector/backend，不修改 LeWM，不报告优化加速比。全链和剩余必要关系接通后，再交付完整程序分解与可查询图的说明。
