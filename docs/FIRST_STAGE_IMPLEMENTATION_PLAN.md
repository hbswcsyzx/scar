# 第一阶段：完整跨层程序模型的执行计划

2026-10-26。用户明确：**完整建模、自动建图；软件深入runtime API/kernel，硬件
覆盖CPU/GPU、DRAM和实际存储层次；不需要机器指令层。** 当前OPEN。任务完成前

## 1. 类型判定合同

核心实体是Operation、Value、StateLocation、Region、Resource；它们有具体操作、
数据/引用/状态、协议、物理资源和证据的细分类型。五个大类不能代替具体建模。
每类需写清程序对应、身份/生命周期、必需端口、连接规则、生成依据和适用版本。

- 输入/输出是端口角色，常量/不变量是带范围的性质；不能与基础实体混为互斥类型。
- AST类型、实际dispatch、效果、alias和纯性分开判断；知道操作类型不授优化许可。
- 资源层次、协议、介质分轴。NVMe不等于SSD，rotational=0不证明SSD，GPU内存
  不一律叫HBM。未知属性不能靠名字补齐。
- 本机实测表明目录名含`/nfs`的数据路径实际为ext4→device-mapper→NVMe；路径
  仅作定位，以mountinfo/dev/sysfs及原运行证据判定。
- 资源存在、被程序使用、分配、完成、结果可见分别建模，不能相互替代。

## 2. 必须连通的层次

```text
入口/模块初始化
  → 函数、方法、循环、分支、异常、闭包与状态
  → 依赖库、PyTorch module/operator
  → 原生/runtime API、系统调用、GPU kernel/copy/memset
  → CPU/GPU、DRAM/device memory、文件系统/块设备/控制器
```

不以Python标准库作为统一终点。有源码/原生图的部分恢复内部结构，明确的库/
OS/CUDA接口保输入输出、状态、效果、失败、资源、生命周期与顺序。空壳/OPAQUE
不算已展开。机器指令、GPU SASS及SM/cache电路内部不是本阶段任务。

全过程包含配置/模型/数据加载、解析/反序列化、CPU处理、搬运/物化、推理/规划、
环境交互、render、视频编码和文件保存。视频/Tensor保存使用同一基础类型和依赖
规则，不按业务名增加特例。

## 4. 交付条件

规范记录、有序Use/状态/控制边、Region及跨层引用只有一个事实来源。磁盘分片/
manifest/index表示这张逻辑图；临时SQLite可重建，物理分片不是优化单位。
值内容可以符号化，但必要的producer、状态和资源依赖不能消失。

最终从同一通用入口自动得到完整模型，可从已建模操作追到输入/状态/控制/资源及
结果，并保留未执行路径的静态结构。类型有表达位置、自动恢复、执行对应和依赖
闭合分别验收，不能以单测总数、AST分类率或某一层100%替代整体完成。
合同及当前细项见[FIRST_STAGE_MODEL_CONTRACT.md](FIRST_STAGE_MODEL_CONTRACT.md)、
[FIRST_STAGE_GAPS_20261026.md](FIRST_STAGE_GAPS_20261026.md)。

## 5. 全面且轻量的实施约束

- 全面指实体、必要关系和实际执行分母完整，不是保存所有数值或重复材料。
- 静态定义、签名、source上下文、资源描述和原证据共享一次；动态发生以限定ID
  引用，不反复内嵌整份源码图、scope、artifact声明或完整证明。
- 每次调用、必要的有序Use、状态版本、写入、alias及完成关系不能因去重丢失。
  相同shape/metadata/样本不允许合并逻辑内容版本；Tensor全量迭代数值默认不保存。
- 同一实际分析会话复用已解析的声明、索引和不可变事实，避免每次查询重读大图、
  重算整文件SHA或重新验证全部source层。缓存必须受原来源/版本/失效合同约束。
- 采集器自身的事件与工作负载分开；避免为采样反复产生子进程或不必要同步。
  原始日志仅保必要的关联/验证依据，规范图与历史/诊断/临时索引分别计空间。
- 记录采集、建图、查询的wall/CPU/RAM、stored/decoded读取和输出成本。当前编码
  重复与采集开销尚待优化，不宣称已轻量。截断/丢失使相应覆盖OPEN，不以丢信息
  换取表面的速度或完成率；表示压缩必须保持原图和端点含义。
