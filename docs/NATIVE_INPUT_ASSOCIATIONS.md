# Native input metadata associations

`import_capture(..., components=("native",), schema_contracts=True, bundle_partitions=True)` is an explicit internal component selection. Its default remains the original native + OS import. The selected fragment is from the actual capture Run; omitting OS does not complete the whole model.

After ordinary `bind_capture_coordinates`, call `bind_native_capture_batches(..., input_metadata_budget=NativeInputIndexBudget(), on_verified_input_shard=callback)`. The existing batch factory acquires its owned source once and constructs the same canonical ProgramSnapshot and verified execution shards. The callback receives `(verified_shard, metadata_session, associations)`; `metadata_session.check(shard, candidate)` independently verifies original producer, slot, source, ValueOccurrence and provider-epoch references.

The input companion uses its existing strict reader and declared chunks. A disposable authenticated SQLite index holds provisional rows until successful source EOF/SHA verification. A single full Kineto pass joins event-tree correlation ID to the exact CPU External id, then Record function id to the owned ETO RF/thread/node ordinal. Equality of correlation ID and RF ID is never a join. The ETO source is reused from the already verified batch acquisition. Ordered Tensor and TensorList paths, empty lists, zero-dimensional Tensor metadata and opaque slots stay distinct. Every retained row and metadata path is accounted for, including unavailable schemas, bridges and canonical boundaries.

Associations retain the existing NativeInputRef, ValueOccurrence, OccurrenceEvidenceBinding, original ProviderFactReference and source locators; there is no new value graph. A same-provider allocation ID may reference a unique original positive birth in the same owned profiler/process/device domain. That reference does not establish canonical allocation ranges, alias, value contents, a LogicalVersion or readiness. Tensor implementation pointers and matching shapes are never logical identity keys. Native outputs remain unavailable in the pinned metadata API.

`query_native_input_associations(manifest, expected_sha256=..., row=..., node_id=..., native_input=..., associations=True, limit=...)` loads ordinary published chunks by their stored and decoded receipts. `row` refers to the original one-based companion index. `associations=True` returns port associations; its default returns retained row dispositions. Queries restore no owner and grant no producer qualification beyond the recorded result.

The source passes, private-index cap, output cap and wall limit are explicit in NativeInputIndexBudget. The index is private navigation, cannot be loaded as an owner, and is unnecessary for querying published results. A complete companion denominator is separate from the subset with canonical native boundaries, Python-held identity, geometry/allocation, content, state or ready qualification.

Counts use separate denominators. `retained_rows` and raw-key joins count original TorchOp rows. `metadata_paths`, exact-native-path checks, provider-epoch links and `metadata_dispositions` count Tensor leaves. The disposition counts partition all exposed Tensor metadata leaves; the frontier counters describe overlapping obligations and must not be summed as another partition. Canonical nodes count verified invoke boundaries, including zero-Tensor calls. The companion storage-offset gap is only a gap in that provider binding: ETO Tensor tuple item 2 and previously qualified StorageRegion facts retain their own offset evidence through the original port sources.

For canonical endpoint queries, first run `publish_native_input_port_navigation(batch_report, fresh_out, expected_sha256=...)` over the published batch. It checks the original per-shard qualification manifests and exact denotation/source matches; ambiguous parents reject. The resulting navigation manifest attaches the original ProgramSnapshot, Execution artifact and DenotationID to every association. It creates no new IR entity or UseOccurrence ID. Ordinary reading of an execution can follow the original `(operation, use, value)` UseOccurrence record.

Public association mode requires this navigation manifest; an original metadata manifest supports row inspection only. `node_id` is a retained-row selector; association mode with node_id raises explicitly. Select the original row first and then use row+associations. The API-only native_input selector takes a complete encoded NativeInputRef, scoped by the selected navigation publication. Readers check regular nonsymlink files, explicit versions/profiles and bounded stored/decoded bytes; private indices are unnecessary.
