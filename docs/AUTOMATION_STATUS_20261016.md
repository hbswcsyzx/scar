# 自动建图：交付边界、真实进度与接续验收

日期：2026-10-16。**自动化流程已建立，完整自动 LeWM 依赖图及可靠化简尚未交付。**
本页区分自动发现、局部建图、跨层连接和化简许可；测试数量不表示程序覆盖率。

## 1. 输入必须来自原程序

生产流程的输入是程序入口/命令、项目范围、现有环境、分析预算和行为合同。
SCAR 自动采集执行、发现源码、解析操作、展开区域并建立依赖对应。
不得要求用户提供 LeWM 函数名单、常量清单、纯函数声明、手工依赖边或 workload 图。
手工 IR fixture 用于检查核心模型，不能作为自动建图验收证据。

```text
原程序入口/命令
  → 自动源码发现与执行采集
  → 源码结构 ↔ 实际调用/操作证据
  → 值、状态、控制、完成与区域接口依赖
  → 从要求保留的输出和效果反查依赖闭包
  → 带条件、位置、残余效果及成本的化简指导
```

当前生产流程主要接通前两步及部分局部依赖。不能将已索引源码、已观察调用、
局部图合法或同一引用，直接升级为完整程序恢复或变换许可。

## 2. 图里表示什么

| 结构实体 | 含义 | 自动恢复的目标关系 |
| --- | --- | --- |
| Operation | 读取、写入、计算、调用、复制、分配、等待等具体操作 | 有序输入使用、输出、状态访问、控制和完成 |
| Value | 数据、引用、区域参数或状态版本 | 准确的产生与使用位置，参数/返回、分支/循环携带值 |
| StateLocation | 可变内容或外部状态的位置与范围 | 读写版本、alias、覆盖、逃逸、外部变化 |
| Region | 带入口、出口和接口、可递归展开的子图 | 词法包含与实际调用分别对应，正常/异常/循环出口完整 |

这四类是结构实体，不是全部操作或全部图层的节点类型。Operation 有可组合的
基础行为类型；Resource、StorageRegion、Materialization 和动态执行事件有各自
类型。输入/输出是端口角色；常量、不变量是需证明且有作用范围的性质。
一行 Python 可以展开成多个操作。import 包含解析、加载、初始化和绑定变化，
不能因最后读取一个数值就抹去其余依赖和效果。

源码结构、执行证据和优化区域视图分开保存，以有类型对应连接。相同源码模板
可以对应多次 invocation；相同逻辑版本可以有多个 materialization；同 storage
可以有多个 view；同 object 可以经历不同内容版本。这些对应尚未全部实现闭合。
基础定义见 [程序类型](PROGRAM_TYPES.md) 与 [核心模型](CORE_GRAPH_MODEL.md)。

## 4. 关键难点与处理方式

1. **跨调用来源必须按位置连接。** 名称绑定、receiver、defaults、partial以及
   callee换code会改变实际调用。采集有界 load occurrence、attempt、真实entry和
   completion，按实际指令路径与输入Use路由；同次 `f(x,x)` 保留两个位置。
2. **代码身份不等于函数环境。** 同code可以配不同globals/closure/defaults。
   给函数环境独立引用端口，读写明确携带状态版本；先保留coarse world，关系闭合
   后再拆细，不能用“图内没有看到写”证明恒定。
3. **循环和可变数据要跨迭代连接。** 建立循环入口/回边/退出接口和loop-carried
   值、状态；处理原位覆盖、dict/对象字段、view、外部NumPy写入及RNG。
   LogicalValue/Version与storage/materialization分开，用操作来源建立对应。
4. **观察范围和观察干预要显式。** 动态import、未执行分支、native/GPU实现以及
   hook/预算缺口不能由一次trace补全。源码与runtime互证；缺口给出具体位置、
   所需证据和受影响查询。对已支持的常见结构实现规则并用反例收紧，不能长期
   用一个无差别UNKNOWN阻断全部优化。
5. **化简需要完整观察根和成本。** 从合同要求的结果、状态、异常及外部效果反查
   依赖。提升需证明依赖在目标层可用、相关状态稳定、控制/异常/完成关系允许；
   常量替换及删除import还需分析残余初始化效果。只有证据和成本足够时才给方案。
6. **Python到GPU需要实际执行对应。** 接续工作还须把module/operator与profiler的
   kernel、copy、sync对应，并保留异步ready/order接口。`.to()`调用不能直接算
   transfer，view不能直接算完整allocation。复用已有采集与库级操作接口，不为
   workload编造行为；当前局部源码core尚未与这些实现证据形成完整依赖闭包。

## 5. 后续自主验收顺序

| 节点 | 必须交付的自动结果 | 必须阻断的反例 |
| --- | --- | --- |
| R1已验收 | 原归档5个旧mismatch完整descriptor重现；旧v1/v6按历史profile重放 | 源码漂移、同文件不同flags/compile filename缓存混用、弱化匹配 |
| B1/B2 + 环境/C2 | 原始多文件命令自动建图；公开查询从指定call result穿过多层actual/formal/return回到准确上层Use，承接环境与后态 | shared object多参数、两次调用、动态defaults/receiver、重绑、异常、hook缺口 |
| 循环与细状态 | 原始程序自动恢复循环携带依赖、对象/存储alias、版本和copy来源 | 零次/多次/提前退出、原位修改、共享view、foreign write、RNG |
| 区域依赖与化简指导 | 从观察根求依赖闭包，给出准确范围、替换/提升位置、保留效果、条件和成本 | 仍有消费者、逃逸、异常或外部效果时误删；只凭重复节点复用 |
| 原LeWM复验 | 无手工补图，沿上述公共流程自动产生可检查指导；若以后应用修改，再分层验证并clean A/B | workload名称规则、把候选当获批变换、把插桩时间当加速比 |

每门自行验收：冻结实现→通用正反例→必要回归→真实未修改输入复验→记录失败和
通过证据→提交推送。可用明确小范围规则逐步覆盖，完整端到端要求保持不变。
当前不增加detector/backend。细化实现见 [跨层连接计划](N2_CROSS_CALL_IMPLEMENTATION.md)。
