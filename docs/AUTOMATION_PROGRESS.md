# 自动拆解与建图：进度、缺口和后续验收

日期：2026-10-15。本文区分实现、测试通过和外部程序验收。

## 1. 自动化要求与当前结论

目标输入是程序入口、运行配置和需要保留的行为合同。SCAR 自行发现代码范围、
恢复操作及数据/状态/控制连接、采集运行证据，最后输出具体子图化简指导。
用户无需逐个选择函数、标记 Tensor 版本、制作 workload 图或声明某模块 pure。
手工构造 IR 只用于测试图校验器，不算外部程序自动建模成功。

**目前还没有完成整个 LeWM 的自动依赖图，更没有验证过 LeWM 加速。**
已有有限函数体自动构图；新的自动范围清单不再要求用户逐个点名函数，但仍是
候选源码关系与若干独立 body 图，不能冒称完整程序模型。

## 2. 目前能够自动做什么

| 阶段 | 实际实现与证据 | 未成立的结论 |
| --- | --- | --- |
| 有限函数体构图 | N2.a `429e87e`：参数、逐 use 绑定、分支合流、normal/raise、条件调用接口；204 gate / 1,274 回归通过 | 一次函数体成功不等于全程序成功 |
| 入口到候选源码范围 | N2.b0 `f21eb53`：本地 import、父包初始化、相对导入、重导出、歧义/动态边界、文件与字节预算 | 候选搜索根不等于真实 sys.path/loader；发现不等于运行可达 |
| 自动接口与覆盖清单 | 每个成功准备文件的定义、调用、定义时/调用时阶段、源码位置和覆盖状态；自动尝试 body lowering，无人工函数列表 | CONNECTED 仅表示有核心对应，不表示效果完整或可化简；准备失败必须单独报告 |
| 跨文件候选连接 | 从 callee binding 和 import 源见证到候选定义；保存控制条件；重导出路径去重并受预算限制 | 实际 callable、重绑定条件和跨 body 状态接口尚未闭合 |
| 持久化与自验 | JSON/gzip、源码快照、typed 对应、独立预算的当前源码重放；N2.b0 冻结代码 267 gate tests 通过 | 该 gate 测试通过不是 LeWM 外部压力验收通过 |

公共入口：

```bash
conda activate lewm
scar inventory-program /path/to/project/entry.py --project-root /path/to/project \
  --out artifacts/reports/program-inventory.json.gz
scar check-inventory artifacts/reports/program-inventory.json.gz
```

这不是任意 shell command 到完整运行模型的入口；配置、动态加载及真实执行
对应还需下一阶段接通。普通 `model-program` 仍保留供单个函数体诊断。

## 3. 什么才算图已接对

结构类型使用 Operation / Value / StateLocation / Region；行为类型、具体操作
规则和关系分别定义，不能把四个结构类别当成所有操作的完备解释。

```text
源码版本与位置 -> Operation + Region
有序实际输入   -> Value -> 特定 use -> Operation -> 结果 Value
可变对象       -> ReferenceValue -> StateLocation -> StateVersionValue
控制/完成方式  -> 入口、分支、逐前驱合流、循环回边、normal/raise
调用           -> 每个调用点自己的实际/形式端口 -> 可展开 body Region
运行证据       -> 上述静态定义的独立动态实例与物理物化
```

“同一个函数执行多次”“有相同 shape”或“源码有相同名字”都不能代替这些连接。
现在未知操作使用 coarse world，能保守保留影响，却还不能证明互不影响。
完整优化需要明确读写位置、alias、生命周期、外部效果、异常和消费者边界。

## 4. 本轮外部压力暴露的事实

对未修改的外部 LeWM 启动器 `run_inference.py` 自动发现并构图，不提供函数列表。
`f21eb53` 的第一次完整源码检查持续 **919.862 秒**，未产出最终报告。
经验证进程身份后停止了这个 SCAR 自有分析进程，保留 SIGTERM 和退出码 143。
该尝试是 **未完成**，不是通过，也不是 LeWM workload 运行耗时。

独立 cProfile 显示：单个 154 行外部源码的准备过程有约 3,259 万函数调用，
其中 `record_errors` 调用约 186 万次；同一 SG/操作层被反复校验和重建。
无 profiler 的三次源码准备耗时为 4.110 / 4.108 / 3.934 秒。
这给出了先修 SCAR 自身开销的具体依据。后续外部验收应重跑同一入口与范围，
不能缩小输入后宣称原检查成功。

启动器还使用 `exec(compile(...))` 加载代码；当前已记录 DYNAMIC_EXECUTION
边界，尚未自动恢复被加载文件及其调用关系。把 import 清单称为全 LeWM 覆盖
会遗漏这条路径。

## 5. 后续顺序和自主验收

| 顺序 | 要攻克的问题 | 验收结果必须包含 |
| --- | --- | --- |
| N2.b0 收尾 | 自动范围、接口和共享准备成本 | 同一外部入口自动清单、实际范围/失败/预算、严格重放、分析时间和内存；不需手工补图 |
| N2.b1 | 循环及表达式控制 | 零次、回边、携带局部值/状态、break/continue/else、迭代耗尽与异常；assert 的编译配置和惰性消息求值 |
| N2.b2 | 明确状态与跨层来源 | 属性/下标读写、alias/view、局部重绑定、对象内容变化、逻辑值与物化分离；未知冲突不能消失 |
| N2.c | 初始化和调用连接 | 默认值/装饰器、模块残余效果、跨文件/方法目标和动态加载；重绑定或代码版本变化使旧结论失效 |
| N4 | 真实执行精化 | 自动连接函数/module/operator/copy/kernel/sync 实例；区分 to 调用与真实传输，保留 stream 完成及 autograd |
| N3/G7 | 按观察根化简子图 | 自动给出常量替换、上移或共享的精确边界、use 改接、保留效果、失效条件与成本；证明不足逐项给出缺失事实 |

每门顺序为：规则/接口设计 → 通用正反例 → 实现冻结 → 自主 gate/回归 →
外部压力和报告 → 版本归档及推送。下一门可由新反例调整，但不能降低当前门
验收要求。N2.b1 的细化设计见 [N2B1_PLAN.md](N2B1_PLAN.md)，当前仅为 Proposed。

## 6. 自动化中最难的边界

- **动态 Python**：属性、descriptor、monkey patch、exec/loader 的目标不总能
  由静态源码确定。静态候选和实测目标分开，记录代码/配置/绑定条件，用运行证据
  精化；未观察路径保留边界。不能保证任意 Python 的所有行为都可静态精确求解。
- **数据身份**：对象、storage、逻辑值、来源及内容版本不同。仅有 shape/采样
  只能筛候选；数值相同不证明副作用相同。依靠写入、alias 和来源传播建立版本，
  外部 NumPy 写入等不可见写必须有失效/验证机制。
- **组合效果**：深层计算能否上移，取决于全部输入/状态的最早可用位置、控制
  条件、异常和生命周期，不等于选择一个较浅栈帧。用区域接口和逐路径依赖分析。
- **有限证据与完整性**：一次 trace 只证明观察过的路径；节点缺 consumer 只有
  在相关范围闭合后才支持删除。分别报告分类、依赖精度、运行覆盖和证明状态。
- **分析成本**：共享源码快照和 schema，限制图/见证规模，避免每个函数重建
  同一文件及枚举所有重导出路径；保持报告重放、类型和篡改检查。

最终要交付的是机器生成、可核验的修改指导。当前没有新增 backend，没有
因重复标签自动批准 cache，也没有手工给 LeWM 特判或证明。
