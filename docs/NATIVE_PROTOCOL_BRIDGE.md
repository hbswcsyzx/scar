# Bounded native reference/core bridge

2026-10-23. **Implemented; third bounded actual gate passed with independent
static/actual ABI-order checks. First-stage complete modeling remains OPEN.** This is a modeling
adapter, with no workload rule, detector or optimization backend.

## Scope and identities

The public `scar.trace.native_protocol.bind_native_protocol_window` owns one
retained dispatch prefix (currently sequences1..N, N≤16). It requires ordinary
`bind_capture_coordinates` output, explicit retained capture/native archive,
expected manifest SHA, explicit original capture-model hint artifact and SHA,
fresh output, independent budgets and optional progress callback. A saved report
cannot recreate the in-process owned native evidence session.

Actual BEGIN.operator + normal OUTPUT/END, unique owned ETO span/direct child,
pinned ATen schema, ordered native tree paths, held WeakRef epochs and original
physical marker arguments determine eligibility. No function/workload names,
nearest timestamps or Tensor token/content equality take part. Three selected
raw sources are fully streamed and SHA/count checked; only bounded prefixes and
the actual ETO tail sentinel are semantically decoded. Unsupported/raised/missing
sequences retain explicit frontiers; unvisited whole-capture obligations remain.

A typed ProgramGraph owns the only canonical operations, Uses, reference/data
ports and opaque world states. The schema's flat type/path signature determines
one static definition; multiple actual dispatches produce distinct activation,
visit, operation, value and Use occurrences. The normal and possible exception
interfaces stay separate, with `effects_complete=False`. Dynamic scalar values
do not become static code constants. ETO is an execution provider; a real saved
ATen schema interface artifact is the DEFINITION_GRAPH owner.

Selected original objects, allocation epochs, regions and native instances with
complete actual parent closure are published using the existing ValueGraph and
EvidenceGraph schemas. Their *projection* artifacts have new SHA/qualified
namespaces; original IDs/records and parent manifest/chunk/row witnesses remain
in the projection receipt. These are not wholegraph-qualified ObjectRef or
AllocationRef identities. Region layout is explicitly derived by
`PINNED_TORCH_LAYOUT_V1` from the retained `torch.strided` spelling, with the full
original record and rule retained; projected region fields are not claimed
byte-identical.

`NativePortEvidence` privately retains detached canonical raw-window data and
replays direct-child/schema/ordered-held-reference correspondence. Normal
execution validation first checks exact ProgramSnapshot/model/Run scope and
canonical native input/output ports. Only an exact independent reference match
closes `content_native_correspondence_unverified` for that denotation. The old
no-proof path and generic provider-reference/edge rejection remain. A separate
`native_reference_content_unproved` frontier preserves logical contents, hidden
state, alias completeness, readiness and transformation obligations.

Observed geometry remains attached to its actual marker point. A host return is
not a GPU-ready event. The first bridge creates no logical value/version,
provenance or materialization, no fake allocation and no alternative state IR.
Their counts are not the acceptance target.

## Storage and budgets

`BundlePartitions.selected_records` reads requested ordinals through the existing
whole containing chunk SHA/size/newline checks and returns original locators.
Ordinals only navigate: exact original identities/fields are independently
checked. This avoids walking preceding unrelated chunks or rebuilding the
multi-GB original bundle.

The retained real preflight selected16 dispatches:13 ATen interfaces with4 unique
static signatures,3 explicit out-of-domain schema frontiers. The exact selected
source closure requires5 chunks /79,996,957 decoded bytes. Preflight did not
verify full raw SHA or create authoritative runtime evidence.

## Third gate: independently interpreted ABI order

Only `native_port_protocol.py` changed after the second gate. Its private pure
helper independently reconstructs the schema interface artifact from the
source-replayed signatures and checks the flat native ordinal against original
entry BlockArgument, invoke argument/Use, normal CompletionResult, normal formal,
Return Use, exact actual ValueOccurrence/UseOccurrence and normal transfer.
Scalar/reference/world positions are conserved without granting scalar contents
or state purity. The helper runs at session creation and require_scope; the
generic NativeBoundary contract remains unchanged.

The production pure helper passed the saved correctly ordered4interfaces /
13activations and rejected the internally generic-valid re-sealed wrong
candidate. No saved native ownership was restored for that preflight. See
NATIVE_PORT_ORDER_REVIEW.md and the retained declaration counterexample.

The third actual gate independently ran the normal public scope binder and
native source owner again: **exit0/PASS**,19.26s GNU-time whole wall,
maximumRSS660,880KiB (18.657s in-process). The original positive counts,
546,619,922 native raw bytes,5chunks, source projections and41frontiers remain
unchanged. Crucially, it used this run's genuinely live owned raw session to
attempt a new proof for the wrong candidate's own new ProgramSnapshot/model.
Generic core/execution remained0issues, but the source-owned constructor raised
`NativePortOrderError`:2static native/core ordinal errors and4actual native/Use
ordinal errors. The rejection was not an old-proof scope-hash mismatch. Wrong
Run, exchanged existing input slot, missing original object and the legacy
no-owned-proof gap checks also passed. No authority is reconstructed from a

## Remaining modeling obligations

This bounded bridge has actual reference/port evidence. It has not established
logical contents, storage stability through the native operation, external/NumPy
writes, complete alias/effect summaries, physical GPU completion, source-body
world equivalence or the unvisited full-capture native interfaces. Existing
content-model/protocol validators retain those obligations. General non-prefix
windows and additional provider domains need separate explicit adapters and
acceptance. No LeWM performance or transformation conclusion follows from this
gate.
