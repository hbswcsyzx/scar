# Optional SCAR_LEAN_PORTS_V1 capture

This opt-in profile selects exact immutable code and call sites. It does not infer a whole program from seen callees, sample events, add a graph/identity authority, or change the old instructions/windows defaults and event fields. The public CLI and child bootstrap now pass the typed plan to the existing collectors:

```bash
python -m scar.cli trace --capture-plan PLAN.json --capture-plan-sha256 SHA \
  --out fresh-trace -- python target.py
```

The source-entry stage exports `products.capture_plan` from its live analysis window. `LeanCapturePlan.from_source_entry_plan` uses the original readonly CodeWitness; it does not compile, import or lower the target. A plan selects its declared bodies, not the entire program. Source qualification and complete program coverage are separate.

Only planned code receives a local **CALL** mask: no INSTRUCTION mask or per-opcode rows. Unplanned calls directly crossing a planned boundary retain real call/parent/code, necessary parameter/return references, and completion metadata. Their internals are not recursively retained just because code was seen. Planned re-entry still works; unavailable direct-parent/source proof stays unavailable. Caller/all exit locals are omitted, not fabricated. Ordinary Python-target-v2 facts/receiver roles are reused; a target observation does not authorize its body expansion.

Frame metadata declares the profile and exact receipt-bound `lean-plan.<pid>.json`; operand metadata declares the new versioned rule. The normal reader validates that scope and plan SHA. New `OperandScopedGap` evidence holds an actual code and a real optional invocation: unsupported static sites, local callbacks and missing local owners do not become global hook damage. No invocation is invented. The source-port consumer reuses its normal source/CodeWitness/Use/formal checks and localizes code-only gaps conservatively. Old strong reference-identity routes explicitly reject the new rule; source port binding does not prove reference/content equality or readiness.

Global hook/tool/registered-source damage retains global epoch invalidation and stops that channel. Shared budget/I/O/frame-channel failures still prevent complete qualification. This small gate dynamically checked local unsupported continuation; it did not inject every global interference/failure. Unplanned implementation effects, unknown dynamic targets, threads/children outside scope and state/contents/ready remain OPEN.

Plan lookup uses a source-key index and a private weak CodeType identity memo: full descriptor comparison only on first candidate code, never frame/Tensor memoization. The independent `max_codes` budget defaults4096 and is checked against the recorder; it is not a128-body sample limit. Normal close clears runtime memo, while source hashes are guarded at installation/stop. `from_codes` is a convenience selector over bounded current UTF8 files. The implemented archive-qualified entry-plan adapter instead uses original snapshots and readonly witnesses; the bounded `read_plan` transport does not restore a live catalog or proof owner.

Actual one-program Python+Torch CPU results are in [the report](../artifacts/experiments/lean_capture_profile_20261026/REPORT.md). Capture imports/input construction were explicitly outside scope. The new profile adds no Tensor content reads, Tensor copies/sync or application-value retention beyond existing transient reference callbacks. Existing provider observation/lifetime frontiers remain; no zero-interference claim is made.

The main-tree public CLI also ran from process startup: target exit0/9.140s including Torch import, normal reader exit0/0.022s, 7 entries/exits, 7 calls, 4 handshakes, 0 instruction rows, 2 scoped gaps and no reader issues. Its 34,635 bytes exclude the separate native dispatch observer used in the earlier example, so those byte totals are not an A/B comparison. Results are in `artifacts/experiments/lean_capture_cli_main_20261026/`.
