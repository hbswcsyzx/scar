# N2.b0：自动源码范围与接口清单

日期：2026-10-15。状态：有限范围已自主验收，见
[N2B0_ACCEPTANCE.md](N2B0_ACCEPTANCE.md)；完整 N2 和 LeWM 模型仍未完成。

## 本门必须增加的能力

用户提供入口 `.py` 和项目边界，SCAR 自动发现本地 import 所关联的源码，
记录父包初始化、相对导入、重导出和循环；自动列出所读文件中的定义、调用、
接口与所有尚未支持的语法位置，再自动尝试可用的函数体转换。
不能要求用户逐个选择函数，不能遇到第一个 unsupported 后隐去其他缺口。

范围发现不是运行可达性证明。函数体中尚未执行的 import 也可以扩展候选源码
范围，但必须标注其延迟/控制条件；外部依赖、动态 loader、配置注入和运行时
目标仍是明确边界。源代码数量不能当成运行次数或可优化工作数量。

## 模型与连接

1. **发现层**：物理文件 + SourceSnapshot 是源单元；模块名是某个 source-root
   搜索上下文中的候选映射。同一个模块名可以有多个候选物理文件，不能被
   一个 dict 覆盖。记录 import 的源位置、请求、父包和候选文件边。
2. **接口层**：定义的身份包含源码版本和精确位置；qualname 只用于展示。
   默认值/装饰器属于定义时接口，函数体属于调用时区域，class body 单独记录。
   同名/重复定义不得覆盖；嵌套定义不得错误归入外层 body。
3. **覆盖层**：每条可执行语法记录都有 owner/阶段和来源。分别记录当前
   lowerer 支持、需要其他接口或未支持；这不代表效果已经精确或可以优化。
   注释和仅结构 AST 不能算实际工作。保留调用目标缺口。
4. **核心图连接**：复用 N2.a 的前端、Opcode、CFG 和转换器。每文件只准备
   一次既有源码层；可转换函数自动批量尝试。输出核心图/边界与既有记录的
   typed 对应，避免只写一份无连接的语法计数清单。
5. **重放**：当前源码、搜索上下文、发现集合、定义/覆盖对应和核心图全部
   确定性重建。报告的预算不能自行扩大验证器的独立上限。

静态调用候选仍为 INFERRED，不因此接受 purity、实际 callee、consumer closure
或 import 删除证明。归类和自动尝试不增加 detector/backend。

## 范围与效率

只在项目边界内读本地 Python；不调用 find_spec，不执行 setup.py、pth 或目标。
source roots 与 project root 分开。默认可从项目目录及 src/本地子项目结构发现
候选根；报告清楚列出其推导方式，不能冒称等于运行时 sys.path。调用者也可
提供搜索根。歧义、外部/不可用源码、预算边界和未展开包初始化必须保留。

文件数、源码总字节、目录发现、单文件大小和图操作数有独立上限。不得每个
函数重新建立整个文件的 SG/Opcode/CFG，也不得为每个函数重复保存同一源码层。
只保存紧凑图和引用，默认 gzip；本门不采集新的大 trace。

## 自主验收节点

| 节点 | 需要的证据 |
| --- | --- |
| 范围发现 | 多文件 absolute/relative/reexport/parent-init/cycle；重名、namespace、缺文件、动态边界、预算和不执行目标反例 |
| 定义/接口 | 默认值和装饰器中的调用归定义时；class body 与 method body 分开；重复/嵌套定义不丢失 |
| 覆盖与核心图 | 自动枚举函数，全部缺口有定位；共享准备开销；已有 N2.a 反例不回退；跨文件对应及预算可重放 |
| 公共命令 | 一条入口命令生成压缩报告，严格重放；报告篡改/源码变动/候选新增失效；不覆盖外部文件 |
| 外部压力 | 原始 LeWM 入口自动发现，无逐函数列表/手工补图；记录实际读入范围、缺口、成本和未确认边界 |

实现及反例 → 冻结提交 → 逐项 gate 与必要回归 → 报告提交 → push。
之后进入循环/状态门。若发现本门范围过大，可分提交推进，不能把尚缺部分
从本门完成条件中删除，也不能将有限清单称为完整 LeWM 模型。
