# SCAR 的职责

SCAR 通过程序图解释操作及依赖，最终为合法、成本合理的程序化简和代码改写提供依据。它不需要理解视频或图像的业务含义，也不根据 LeWM 的函数名、变量名或包名套规则。

当前只推进第一阶段，尚未完成：**静态构建可组合子图，动态补充实际执行实例和绑定，共同恢复跨层依赖**。静态已知连接直接保留；动态观察有具体运行范围。字段推理不能代替模块/函数/协议子图的展开和组合。

当前顺序：

```text
静态材料与上下文
→ 语法和作用域
→ 层次化规范程序图
→ 跨过程数据/状态/调用联合推导
→ 属性、约束及效果摘要
→ 可查询的完整结构与明确缺口
```

以后才根据该模型识别化简区域，证明具体改写条件并生成指导；本阶段不增加 candidate/backend、不改写目标、不追求加速比。
纯静态建图不依赖运行证据；显式动态采集用于补充实际调用和数据绑定。成本测量独立，不把采集时间当成目标性能。

完整模型见 [MODEL](MODEL.md)，当前开发顺序见 [STATIC_ANALYSIS_PLAN](STATIC_ANALYSIS_PLAN.md)。
