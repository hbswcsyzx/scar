# 四类顶层实体能否表达 LeWM？

日期：2026-10-13。状态：**源码压力审查；不是运行验证或完整覆盖验收。**

术语说明：本表是基础操作和依赖类型的压力案例，不是业务语义类别清单。
例如保存视频与保存 tensor 应使用相同的表示变换/读写等组合类型，见
[PROGRAM_TYPES.md](PROGRAM_TYPES.md)；不能为每个业务动作增设独立类型。

## 结论

不能将“四类顶层节点方案”说成“LeWM 只有四类语义”。Operation、Value、
StateLocation、Region 是元模型家族；具体操作规则、强类型子类、端口和边
才表达计算、输入、可变状态、控制、效果与实现约束。四类的唯一性、最小性和
对任意程序的完备性均未证明。目前没有发现必须增加第五类的具体反例，
但这不等于所有必要语义已定义或实现。

必须区分四个层次：

1. **可归类**：源操作和依赖有明确存放位置。
2. **有语义规则**：输入、输出、状态、别名、异常、顺序及适用条件明确。
3. **能构图并查询**：从程序自动恢复这些关系，准确回答依赖及状态变化问题。
4. **能指导化简**：据此证明具体子图替换并给出消费者改接与残余效果。

当前四类新核心主要处于设计层。既有有限前端/证据实现不代表本表已自动构图。

## 当前需要补实的规则

- **状态规则**：字典/队列/字段与 Tensor 切片的读写、别名及状态合流；不能仅
  用未填充的 state_slots 接口代替。
- **控制规则**：调用进入/返回、零次循环、异常退出、条件缓存的 hit/miss
  路径及跨调用状态传递；不以一次 trace 覆盖全部路径。
- **算子规则**：明确纯值计算、原位写、view、随机采样、分配和初始化的区别；
  规则必须有 dispatch、类型及实现条件，不能靠名称认定。
- **梯度规则**：数值身份与求导连接分开；不能将默认 CEM 的 inference_mode
  泛化到全部 planner。此审查未完成一般 autograd 语义设计。
- **异步实现规则**：CPU launch 返回与 GPU 完成不是同一事件；值的语义可用性
  与物化 ready 状态分别表达，并连接 stream/event/order。具体运行事件属于
  EEG/实现图，设备或完成条件可观察时仍须进入相应语义合同。当前四分类不提供
  完整的异步完成模型。

## 如何验收是否够用

N1 起逐步将上述模式缩小成通用程序，每个模式至少检查：精确 producer/use、
读写位置、不同控制出口、跨区域绑定和所有要求保留的效果。必须有区分相同
值但不同身份、相同引用但不同状态、相同前向值但不同梯度、launch 返回但值
未 ready 的反例。规则未支持时报告具体缺口，不把占位 Operation 计作语义覆盖。

N1 先验收已规定的小程序接口；其余模式分别进入 N2—N4 或独立后续门，不能
借 N1 的通过宣称整个清单通过。若遇到无法自然表达且无法验证的新实体，应
修改元模型，包括必要时增加顶层类别。类别数量不是验收目标。
