最终使用方式必须是提供原程序入口/命令、环境、资源预算和行为合同，SCAR 自行
拆解、抽象、连图并给出可检查的化简指导。不能要求用户列函数、标记 LeWM 的
常量、声明某个业务模块纯净，或手工连接 workload 图。手写 IR 仅用于核心测试。

当前已经自动完成源码范围发现、源码定义/调用索引、有限函数体转换、调用采集
和代码版本核对；**没有完成整个 LeWM 的统一依赖图**。最新冻结主线为
`8eeaffe`（实现源指纹见 C0 报告）：原始入口自动发现 151 文件、2,217 定义和
10,235 源码调用。在 256 次 body 尝试预算下，44 个 body 生成带缺口的局部图，
212 个不支持，1,961 个定义未尝试；其中也包含需要不同作用域接口的定义。
这些数字不是整体完成率，源码索引记录也不等于已连好的计算/状态依赖。

新真实 calls-only 证据自动采集 84,319 个入口、168,638 个事件；548 份代码描述
核验对应 421 个源码定义。但旧自动展开队列没有消费这套新见证；实参到形参
仍停在 `ARGUMENT_ROUTING_UNVERIFIED`。这是具体的连接缺陷，不能用增加候选
数量代替修复。当前没有 LeWM 可信 TRANSFORM，也没有 clean A/B 加速比。

### 需要攻克的关键问题

- **分类和连接是两件事。** 行/操作类型可以完整登记，但值的精确来源、实际
  目标和状态效果需要对应规则与证据。目前局部图尚未自然组合成全程序图。
- **动态绑定。** CALL 回调看到的 callable/receiver 不必等于源码 Name 当前值；
  同一引用也不能确定来自哪次实际参数。采用指令/求值位置与真实入口握手，
  对不能证明的条件逐项保留义务，而非伪造确定边。
- **状态粒度。** 当前 coarse world 能保留未知效果，却把很多互不相关的状态
  串在一起；这种粗度不能指导有效化简。后续必须精化位置、alias、内容版本与
  logical provenance，不逐轮保存 Tensor 全值，也不以采样相等当正确性证明。
- **第三方库与 import。** 当前源码范围仍有外部/未解析边界。最终须按依赖
  自动定位环境中的源码，建模模块初始化与被消费值，或连接有版本的基础操作
  接口；不能手工指定某个包“只需常量”，也不能因其不在项目目录就忽略效果。
- **分析成本。** 上轮全引用报告未压缩达约 690 MB，公共重放峰 RSS 约 5.1 GiB。
  选取代码目标不需要这套引用向量。先共享单遍校验并输出紧凑来源，再按具体
  查询展开所需子图；同时报告截断和未覆盖部分，避免以默认预算掩盖缺口。

## 自动化验收口径

输入原始程序入口、项目范围、预算及可选真实执行证据，由 SCAR 自动发现源码、
建立类型化实体、连接精确依赖、递归展开候选区域并输出覆盖和证明义务。
不输入 workload 函数名单，不手工修补 LeWM 图，不按业务名称识别优化。
手工 IR 只用于验证核心图自身的通用测试。

“所有源码都有分类记录”“有局部有效图”“完整依赖已连接”“允许化简”分别验收。
预算外、未支持执行结构、运行目标未证实、状态来源缺失分别记录，不以一个
笼统 UNKNOWN 代替原因，也不把未证实的边当成已存在的依赖。

## 模型中的部分与连接

| 类型 | 含义 | 必须连接的关系 |
| --- | --- | --- |
| Operation | 调用、读取、计算、转换、分配、复制、同步等实际操作；可组合行为标签 | 有序输入 uses、产出、状态访问、完成和控制依赖 |
| Value | 数据值、对象引用、状态版本；input/output 是端口角色 | 精确 producer/consumer、formal/actual、分支与循环合并 |
| StateLocation | 可变内容或外部状态的被读写位置 | 读写范围、前后版本、alias、RNG/设备/环境依赖 |
| Region | 带入口、出口和可观察效果边界的子图 | 嵌套/调用接口、循环携带状态、异常与控制可达性 |

源码结构、执行证据和优化区域视图保持分层，通过来源与接口对应。
这四类结构实体不是四种互斥操作，也不证明 Python 的全部执行结构已经实现。
当前细粒度状态连接仍缺失，局部 body 主要通过粗粒度 world state 保守连接。

## 按依赖顺序推进

| 门 | 工作与难点 | 自动自验要求 |
| --- | --- | --- |
| N2.signature | 分离定义时求值、调用绑定、已绑定 body；defaults 是函数状态；装饰器可替换目标 | 全部参数类型、显式 slot/port/use、默认状态与空 pack 计划；正反例、旧版本重放、原 LeWM 同预算复验 |
| 逐调用与返回连接 | 当前接口只有条件入口；实际 callable、normal/raise 和跨文件状态域尚未闭合 | 两层跨文件调用能回到对应调用点；绑定前失败与 body 异常分离；状态不能错误恢复 |
| 循环连接 | 分支、迭代、异常及动态 dispatch 会改变执行次数和状态 | 自动生成携带值/状态与控制边；参数层层传递可回溯，不能错误跨越条件、异常或效果 |
| 状态与逻辑来源 | object、storage、内容版本、view 与物理副本并非同一身份 | 自有状态版本和 provenance；copy/deepcopy/transform 各自按效果规则处理；外部写入使旧版本失效 |
| 子图化简指导 | 相同输入之外，还要满足可达性、结果/效果、状态及资源代价条件 | 从输出/效果反向依赖，逐项生成保留、替换、提升或删除的具体指导及证据；反例必须阻断不合法化简 |

每门顺序：冻结实现 → 定向与独立反例 → 全仓必要回归 → 不改原程序的外部复验
→ 记录实际覆盖、失败和成本 → 版本提交并推送。完整闭环前不添加 backend。

### 具体攻克方式

1. **跨层传递**：用 actual→formal→use 的精确对应识别原始依赖，收集区域的
   最小输入及效果集合。可提升位置还必须满足定义支配、循环变化、异常时机和
   状态约束；仅有“第 3 层输入传到第 8 层”不能确定合法插入点。
2. **逻辑身份**：同一来源不必相等；变换通常产生新逻辑值，复制可产生同一
   版本的新 materialization，view 共享 storage 的区域。Tensor shape/少量
   采样用于便宜筛选；不逐次保存全部数值，也不以采样相等证明内容相等。
3. **动态 Python/外部库**：源码候选与运行 callable/code/状态证据分别核验；
   缺失信息输出具体义务和所需证据，保留异常、import 与外部副作用。
4. **可执行的化简规则**：将恒定值传播、依赖裁剪、循环不变计算提升和精确复用
   写成区域替换规则及适用条件。代价模型比较合法方案，原始执行始终可选；
   不用节点重复或模块名称直接批准复用。

第一门已有限验收；197份绑定计划的调用方尚无成功core，44个成功body中的
110处CALL又均缺目标候选，两组没有交集。这是下一门要打通的实际缺口。

中间 frame 路径、形参/局部/返回引用。引用采用生命周期 epoch，不读取或保存

采集器、代码快照及独立采集反例95项通过。冻结实现`bedcd2d`的有限组件门
659项与全仓1,694项通过，但完整调用连接门仍未验收。独立审计复现并已修复
三个可信性问题（原缺陷如下）：

1. 离线 parent 校验未充分检查活动区间，可能将 child 接到已返回的同代码调用；
2. 采集 metadata 的字节数、未闭合调用和预算等尚需从原始记录重新核对；
3. 仅用源码形参计划和同一引用，可能把 bound method 的 receiver 来源错接为
   显式参数。`Name` 也可保存 bound method，按 `Attribute` 特判不能解决。

这些反例来自通用原始 Python 程序的自动采集，不是 LeWM 专用案例。修复应先
拒绝虚假的确定边；实际调用约定证据不足时，在该处显示具体边界。原先要求
跨多层精确回溯输入的验收仍然有效，不能用停边后的局部结果冒充已经通过。
