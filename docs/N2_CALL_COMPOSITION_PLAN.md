# N2 后续计划：逐调用接口与区域组合

日期：2026-10-15。状态：**Proposed**。本阶段不实现新 detector/backend。
前置为 [N2.function interfaces](N2_FUNCTION_INTERFACES.md) 的有限验收。

## 目标和当前断点

SCAR 要自动建立可穿过调用层级、返回至正确调用点的依赖关系；独立函数体与
条件 actual→formal 计划只是前置。`cfad419` 仍缺少：

- callable 的具体 use 与函数对象/defaults 状态、定义阶段完成条件的连接；
- captured cell 与函数实例/外层 frame 的关系、内容版本及 nonlocal 状态；
- 逐调用的正常返回引用/内容、异常与前后状态对应；
- 多文件 coarse world 的显式状态域映射；
- 循环逐前驱携带的值与状态、终止和异常边；
- 自动推导的细粒度 location/footprint/alias 及 provenance。

不能因为 body 图有效、源码目标匹配或绑定计划完整，就填入确定 callee。
当前 return 建模也含 opaque 操作；`return x` 尚不能一般地穿透为输出引用
身份等于输入引用，更不能据此删除 frame 清理效果。

## 建模约束

1. **区分不同关系的强度**：来源、条件接口、已观察调用和已核对执行对应分别
   记录，保持各自锚点、条件和失效原因。code witness 不证明 callable 绑定
   或 defaults 未变化。
2. **逐调用实例化边界**：共享源码 body 不等于共享动态调用。形式入口、局部
   frame、正常/异常出口、状态必须对应当前 call；递归和两个调用点不得串线。
3. **区分失败阶段**：actual 求值、展开、dispatch、绑定可在 body 之前失败；
   body 抛异常可能已经改变状态。不得把所有 raise 都接到 body 的 raise。
4. **显式状态域关系**：不同文件 world ID 只是分析命名空间；组合必须说明
   哪些状态承接、冲突或未建立对应，不能由不同 ID 推导不相交。
5. **按需递归，保留边界**：从入口/观察根/调用需求展开，预算和递归边界可
   重放。未闭合部分输出具体依赖义务，不用手工 workload 图绕过。

现有归档 trace 缺少的 callable/actual/状态身份事实不能靠离线解析补造。
C1 审计须列出已有字段和所缺证据，再设计最小运行采集：引用身份、版本、
来源及必要关系为主，不保存每次 Tensor 的全部数值。新的真实采集须单独验证
开销与映射；当前外部来源压力测试只能验证其已有证据支持的范围。

通用操作规则同样是必要工作：例如引用传递、标量操作、属性访问和 PyTorch
操作各自明确结果关系、读写/alias/异常效果及适用类型条件。AST 中的 `+` 可以
触发用户定义行为，不能仅按语法分类为纯计算。这些规则逐步细化 coarse world，
让以后子图化简能实际解除证明义务，而不是继续积累未连接的候选。

## 自主验收顺序

| 门 | 交付 | 必须通过的自动反例 |
| --- | --- | --- |
| C0 | 先审计正常 return 引用、退出效果与调用完成接口，确定有限支持范围 | `return x` 的身份关系与 frame cleanup effects 分别描述；局部引用不能逃逸至另一调用 |
| C1 | callable/default/captured-cell 状态与条件调用接口 | 名称重绑、decorator 替换、修改默认布局保留阻断；同源码不同 actual/cell 实例不混用；外层 nonlocal 更新传播 |
| C2 | 逐调用入口、normal/raise 和状态域对应；通用跨文件依赖查询 | 两文件 caller→helper→return 可以回溯；helper 修改状态后抛异常不能回到旧状态或正常出口 |
| C3 | 有限循环 CFG、逐前驱携带值/状态与终止要求 | 零次路径、下一轮读更新、break/else、迭代器修改后抛异常、无限无结果循环 |
| C4 | 细粒度读写/alias/版本和数据来源规则 | `y=x; write(y); read(x)`、view 重叠/不重叠、外部 buffer 写入、独立可变结果不能直接合并引用 |
| C5 | 观察根驱动的跨调用/循环依赖闭包 | 输出、状态写、交互、异常和终止要求保留；缺口定位明确；可能抛异常的循环体不能无条件外提 |

这些门按依赖实施，不承诺一个提交支持全部 Python。每门必须提供原始源码
fixture 自动构图、独立反例、版本/预算篡改重放、冻结回归和外部来源报告。
只在真实结构连接建立后，再将已实现的规则接到具体化简指导。

## LeWM 外部核验口径

继续从原入口＋真实 trace 自动发现，禁止函数名单或人工修图。
比较同一预算下：当前阻断的逐项迁移、可穿过的调用/返回/状态链、未证义务、
分析时间、内存和磁盘成本。源码/trace/原仓库前后哈希保持。
结构覆盖不等于实际 callee 已验证；分析时间不等于 workload wall-clock。

在得到可信修改指导和实际变换之前，LeWM 加速比继续记为**尚未验证**。

## 本轮自动来源审计给出的优先级

新报告的197份绑定计划涉及478个actual，尚无core UseID：调用者146份
NOT_ATTEMPTED、51份UNSUPPORTED。44个成功body中的110处CALL都能对应到
源码调用，但这些调用均无源码目标候选；两组调用没有交集。这是当前覆盖与
目标解析缺口，不能写成已建立197条运行数据流。

原17个首先受旧签名阻断的观察来源候选，2个现在产生body；其余15个暴露
7个closure/cell、8个语法接口阻断。因此C1需要明确处理捕获环境，同时
优先为已有body调用建立目标关系，再接C2出口；不按工作负载函数名处理。
这些计数来源于自动ID/SourceReference join，仅用于确定开发顺序。
