## 本次保留与压缩

- Git 历史、源码、配置、验收报告与环境基线保留。
- SCAR 生成、未纳入 Git 的大型 JSON/JSONL 改为同名 `.gz`。原始文件删除前
  核对解压内容 SHA256，并记录原名、归档名、大小和哈希；不损失原始事件。
- 已有内容一致的 gzip 归档直接复用；内容不一致则保留原文件并记录原因。
- 清理项目内 Python/pytest 缓存、build 和旧 wheel 安装测试副本。共享 pip/
  conda 缓存、LeWM 代码/数据/环境以及其他项目不在清理范围。

事件 reader、v2 normalizer 和 CUDA profiler importer 自动识别同名 `.gz`，
用户仍可传原来的 trace 目录或文件路径，无需手工解压。事件 reader 改为逐行
读取，避免 read_text/splitlines 的额外整文件副本；最终事件图仍会占用内存。
其他暂不兼容 `.gz` 的旧消费者可由自动化步骤临时还原文件，消费后移除临时
副本；不应长期留下重复解压副本。
原始路径和归档路径的对应关系均在清理记录中，不修改历史报告的内容哈希。

## 后续实验约束

1. 大图/trace 优先分块或压缩写出，保留小型摘要和源文件哈希。
2. 一般 profiling 不默认启用逐行追踪；需要时限制阶段、范围和记录量，并
   明确记录截断/未覆盖部分。不能再让短实验产生 10 GiB 级逐行输出。
3. 衍生图优先按需重建，避免为每种查询保存一份完整重复图；报告只保存
   查询证据与必要切片。
4. Tensor 记录以身份、版本、shape/dtype/device/provenance 为主，采样仅作
   便宜的差异筛选。采样一致不能成为完整内容相等或优化正确性的证明。
5. 每次压力测试报告新增磁盘量、峰值内存、耗时与覆盖范围。测试临时安装
   和缓存应在流程结束时清理。
