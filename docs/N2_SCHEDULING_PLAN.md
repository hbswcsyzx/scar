## 实际问题与模型

上一门 LeWM 来源索引中有 27 个候选函数因预算未尝试。当前逐文件先构完全部
body，文件内优先观察定义仍会消耗后续文件需求的预算；lowerer 在每个 root
内又自行展开同文件候选。这两层必须同时改变。

程序结构仍由 Operation / Value / StateLocation / Region 表示。新增 expansion
是 **SCAR 自身分析工作的调度账**，不是新的程序行为，也不授予优化权限：

```text
入口/已有 trace -> 共享发现 -> 每文件索引/精确来源核对
  -> 全局定义与条件调用需求 -> 按优先级单根 body 构图
  -> 聚合 FileInventory、来源对应和运行定义/core 连接 -> 严格重放
```

每项任务绑定 SourceReference + DefinitionID。优先级依次是观察代码的函数
来源候选、入口/已需求区域中的条件 call 候选、其余函数。观察的 module/class/
thunk 不伪装成普通函数任务。相同定义只调度一次；重复事件不重复编译或建图。
源码候选不是 live callable，需求分类不是执行可达性或 effects 证明。

调用见证同样按需求延迟分配，未需求 owner 的调用等到剩余任务之后才补充。
不能在索引阶段先给全部源码调用分配见证：较早的无关调用会耗尽预算，甚至
阻止已观察 body 在构图后发现的同文件目标。旧 v1/v2 仍按原顺序处理见证。

候选调用保留原 import/绑定见证和未知条件；不按名字猜跨文件函数。单根 body
中保留 source_definition 候选但不自行构造其他 body；全局队列统一决定后续
工作。函数图的结果、world、callee 不因调度优先级而改接。

## 有界上下文

重量 PreparedSource 每文件只 prepare 一次。私有 TemporaryDirectory（0700）
保存自生成上下文（文件0600），进程只接受自己的内存索引，不读取报告指定的
pickle。流式 pickle/gzip；总压缩字节与单记录原始字节分别受独立预算限制。
SHA 核对通过才反序列化；不能先生成无界 bytes 后检查大小。不可序列化的
symtable 在恢复时只从封存 text 重建，不再从可能已变化的文件读取。

同时只驻留一个重量上下文。动态发现的交替文件依赖可能使同文件多次恢复，
恢复次数上界为已尝试任务数，不保证每文件固定两三次；不会再完整 prepare。
CLI 独立输出 typed analysis_measurements（恢复尝试、恢复压缩 payload 字节、
压缩写入和接受的原始字节）。这些是 SCAR 自己的成本，不进入语义重放身份，
不解释为 LeWM 的内存、传输或性能。payload 字节也不等于磁盘物理读流量。

默认预算 128,000,000 压缩字节、64,000,000 单记录原始字节。失败写入同样计费，
不退还分析成本；失败的部分文件立即清理。分析完成/抛异常均清理整个目录。
报告保存预算、不可用上下文及任务状态；具体字节/耗时属于本次分析测量，不
作为跨进程确定性语义身份。持久化报告不包含临时路径或 pickle。

上下文预算失败不删除已成功发布的轻量索引和代码见证；对应 body 明确未
尝试。只有整个文件索引失败才清除该文件的来源连接。core 链接在每文件全部
body 聚合完成后一次更新，避免后一个任务覆盖前一个任务的连接。

## 格式与重放

- 无 trace 的默认纯源码清单维持 v1 和旧执行顺序。
- 带 trace 新清单为 v3，增加 typed expansion。旧 v2 报告按历史算法重放，
  不能根据新预算顺序悄悄改变其图。所有旧优化授权仍为 false。
- v3 从当前源文件/trace 重新建立索引、需求及任务顺序，不信报告中的分类、
  来源、计费或结果。验证器的上下文预算独立，报告不能提高上限。
- 新 schema 不代表完整 Python 调用、循环/状态模型或新的 backend。

## 自主验收节点

| 门 | 必须取得的证据 |
| --- | --- |
| D1 模型/临时存储 | typed ledger/预算校验；压缩/原始双限；源码快照恢复、破坏拒绝、异常清理、文件权限 |
| D2 全局执行 | 早期大量无关定义不饿死后续观察函数；不同文件/定义顺序；观察函数的条件 helper 需求；单根不暗中展开 |
| D3 预算与对应 | 成功/失败/回滚均收费；重复定义任务去重；不可用上下文不删索引；最后聚合保留全部 runtime core 链接 |
| D4 公共入口 | v3 CLI/压缩报告/严格重放；源/trace/ledger 篡改和预算自升级反例；旧v1/v2报告可重放 |
| D5 外部/版本 | 冻结实现、mapped gate/全仓回归；相同原始 LeWM 入口/trace/预算自动重建与重放；报告、失败记录、commit/push |

外部验收比较每个观察来源的 body 状态，要求不再被先前文件的 remainder
任务抢占；同时列出真正的语法/接口阻断。若没有新增成功 core 连接，不能
假称图覆盖改善；应据新的明确断点继续 formal/定义/调用接口门。

本门不实现新的优化规则，不改变外部 LeWM，不接受纯性、值相等、callee/
effect 等价或加速结论。父 N2 与完整自动优化目标继续保持未完成。
