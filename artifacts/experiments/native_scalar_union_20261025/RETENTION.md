# Explicit small retention

stage-paths.txt is the only staging authority for this delivery. It includes the
four production files, typed API document, two design/primary-source-receipt
files, pure API preparation, original runner/freeze/baseline source snapshots,
actual result/stdio/time and small public metadata/report/manifest files.
No unrelated scope or publication work is staged.

All graph/program/execution/value/evidence/projection-receipt data, association
rows, parent/dispatch/qualification data chunks and private SQLite remain at
their original local paths. They were only stat'ed for this retention step;
no such data was decoded or newly hashed. Where a small retained report or
manifest already supplies a writer SHA, delivery-inventory.json reuses that
exact artifact descriptor. Missing whole-file SHAs remain null rather than
invented or obtained through an additional data pass. Private SQLite is
stat-only disposable navigation, not owned authority. No file is deleted.

The original same-CPU capture/G1 inputs are referenced by the91 exact input
receipts in freeze.json and their prior committed archives. They are not copied
or rescanned for this delivery. Absolute provider URIs keep their original
meaning; storing a receipt does not silently migrate or re-own its artifact.
Official PyTorch files are not republished: the two-file design preserves exact
revision/URL/SHA/bytes/line-range receipts and the interpretation boundary.

Root confirmed the actual process terminal. Actual gate result/freeze/stdio
are preserved verbatim; this report is a separate delivery consumer. New
retention hashes cover explicitly listed small files only. Bulk writer receipts
are reused without becoming independent post-gate validation. V1 history,
previous native failures and actual artifacts remain unchanged.
