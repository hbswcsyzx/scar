# C2.1–2.3 resumable body integration audit

Read-only audit of the proposed contract in `docs/M1_RESUMPTION_BODY_COMPONENT.md` against tree `b4bc1a42799d96d1e38ea62ae134386f398135a3` (2026-10-17). At this baseline, the new records are not implemented. No tests or workloads were run. This is an integration checklist, not an implementation-pass claim.

## Main risk

A single CFG/dominator graph cannot serve both ordinary availability and resume control flow. A suspend-to-landing edge is a possible future temporal continuation, but it must not make an unsaved pre-suspend value available in the resumed activation. Conversely, excluding it from the logical CFG would break pending-completion facts, cleanup activation, and state-flow analysis. The component needs distinct, centralized projections: ordinary edges; logical edges (ordinary plus temporal); and availability roots/cuts (body entry plus each resume landing).

For example, `x = make(); yield y; return x` is valid only if `x` is in the suspend's saved slots and the landing uses the newly bound `SavedInput` argument. Letting the pre-yield `ValueID` dominate the landing is unsound; treating every landing as unrelated also loses legitimate saved values and an active `finally` context.

## Central implementation seam

The minimum coherent seam is shared derived graph utilities, not independent ad hoc edge loops in each validator:

1. `ordinary_successors(graph)` for existing SSA/ordinary operation order.
2. `logical_successors(graph)` that adds only the validated temporal suspend-to-landing edges, retaining source suspend and case identity.
3. `availability_roots(graph)` plus a single resolver from `SavedInput(saved_slot)` to `Suspend.saved[saved_slot].use` and then that owned Use's value. `ResumeInput(resume_slot)` resolves only to the target landing argument and declared slot signature.
4. Reuse the resolver for base type/reference checks, LOCAL_BINDING, C0 pending, and C1 forwarding. Keep type, identity/alias precision, pending origin, and cleanup activation checks separate; a structural saved-copy fact does not imply object identity or runtime restoration.

Validation should first establish exact record/table/ownership shape, target and unique landing rules, and normal state-domain rules. Then validate temporal availability and body context attachedness. Run binding, C0, and C1 facts over the validated logical projection. Keep malformed graphs from entering query derivations; `ProgramIndex` already calls core `validate` before indexing.

## Compatibility and semantic boundaries

- `FRAME_CONTEXT` is an abstract frame-context token, not a retained Python frame object or proof that a generator exists. `DRIVE_CALLER_CONTEXT` is scoped to one attach/detach interval and cannot be saved or passed to a normal callee.
- Resume state is fresh. Saving the previous world would miss writes performed by a gate/delegate between suspend and resume; the contract correctly requires one `ResumeInput(STATE, location)` for each state domain.
- `SavedInput` proves a declared structural copy of one suspend actual. It does not prove a real runtime drive, exact Python `send`/`throw`/`close` behavior, exception-context inheritance, or one-shot generation. Those remain C2.4/runtime evidence.
- ResumeSlot has a payload class, while the driver request and event generation are intentionally not encoded here. Do not infer NEXT vs SEND(None), cancellation, close, or delegated exception behavior solely from body kind or a matching payload type; the driver interface must supply that correspondence.
- Do not promote body declarations to source legality, static call binding, provider equivalence, or transform permission. The contract itself leaves C2.0/C2.4 and complete model coverage open.

## Small acceptance cases this integration should preserve

1. Accept a value saved before yield, copied into one landing argument, and used there; reject the same graph when that saved slot is removed or the post-resume use bypasses the landing argument.
2. Accept all fresh resumed state domains after a gate/delegate write; reject old state passed via SavedSlot or a missing/duplicate domain.
3. Accept an active C1 cleanup suspension only when saved pending and cleanup context are copied to the landing and cleanup stack is unchanged; reject `ResumeInput` used to fabricate that old pending/context or an ordinary side-entry to the landing.
4. Accept a LOCAL_BINDING only through a saved same-slot token; reject a resume token with another slot or a normal Python Reference used in its place.
5. Keep RETURN/RAISE ExitPort queries and FrameExit obligations terminal-only; verify a yield adds no exit and does not let a resumable body appear as an ordinary CALL/INVOKE callee.
6. Round-trip a v10 graph with distinct `SavedInput`/`ResumeInput` wire records; reject v1–v9 envelopes that carry any new C2 fields/tag/type, and compare existing v1–v9 golden wire bytes unchanged.
