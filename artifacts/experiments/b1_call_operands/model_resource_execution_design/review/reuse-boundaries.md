## 缺少的 canonical 动态接口

在 `scar/ir/v2` 与当前 `scar/ir/program` 搜索范围内没有 `ResourceInstance`, `WorkTicket`, `OperationOccurrence`, `ActivationID`, `RunID` 或 `WindowID` 类型。现有最接近项各自有严格边界：v2 `OperationInstance` 使用旧的 `OperationDefinitionID`；`InvocationKey` 是 call recorder 的局部帧标识；`ProviderRunScope` 的 run/window/clock 是字符串；`MaterializationID` 是表示/存储侧 ID。把任意一项直接改名都将混合不同所有者和生命周期。

也没有一个统一的 typed time base：Event 使用 `perf_counter_ns`，v2 OperationInstance 和 MeasurementRecord 只有 ns 数值、没有 clock ID，provider scope 的 clock 是文字名。不能对不同记录的 `start_ns/end_ns/ts_ns` 排序或计算间隔，除非新 bridge 明确给出 clock domain 与 run/window。

## 有限接口层次建议

保持 `ProgramGraph` 为唯一静态/SSA 事实拥有者，并在其外侧增一个窄的 execution-bridge 层，不复制 core operation、use、value 或 state：

1. **Trace envelope**：复用 `TraceManifest` / `CallTraceFile` 的 SHA、字节/行数和 raw anchor；增加 typed run/window identity，至少按 `(run, process, thread)` 限定 invocation/event 坐标，并为 clock 单独标识。旧 `ProviderRunScope` 可作为输入 metadata，不能当新主键。
2. **Operation activation binding**：每个动态执行 occurrence 有独立 ID，引用一条原始 `InvocationKey`/`CallRecordAnchor` 和一个 canonical `OperationID`（或显式 `RegionID` body activation），并保留 `EvidenceClaim`/状态。只有 source/code witness 与明确 `CallSiteLink`/body link 能给出候选映射时才建立关联；不能靠同 code、静态 OperationID 或 parent 关系合并两次 activation。运行次序和父子控制都要有单独、同一 run/window 内的 edge/anchor。
3. **Resource instance / WorkTicket**：各自拥有动态 identity，分别引用静态 `ResourceDefinitionID` 或外部资源端口，并关联 activation、真实 `UseID`/资源句柄 occurrence、create/submit/dispatch/complete 等原始事件 anchors。它们只记录身份、生命周期和证据，不另建值 producer 或资源状态；当前状态继续通过 core `LocationID`/`StateVersionValue`/`StateAccess` 表达。没有实例 identity/完成事件时保留 UNKNOWN，不能由 `ResourceRequirement`, `ResourceUse` 或 Event.resource 字典补齐。
4. **Materialization correspondence**：保留 v2 `MaterializationID`、`ValueVersionID`、allocation/storage region；增加显式 crosswalk 到 canonical core `ValueID`/相应 state location 和 activation/event anchor。Crosswalk 是对应声明，不制造 `OperationResult`、`UseID` 或 state version。必须分别表示 exact source identity、representation/materialization identity 与 contents/effect proof，不能因 aliases 或同一弱引用 token 互相升级。
5. **Compatibility path**：旧 v2 `EvidenceGraph` / `CorrespondenceGraph` 和旧 `ExecutionGraph` 保持原 schema/读写语义；一个 adapter 把旧实例/观测逐条导入新的 bridge，并把其旧 `OperationDefinitionID` 对 core 的映射留为显式 UNKNOWN/ambiguous，直到有 typed source/core correspondence。v2 `IRBundle` 当前只装 semantic/evidence/values/correspondence/optimization/source-semantics，没有 core ProgramGraph：[`v2/schemas.py:72-84`](../../../../../../scar/ir/v2/schemas.py#L72)、[`schemas.py:86-165`](../../../../../../scar/ir/v2/schemas.py#L86)。不要隐式把两个 bundle 当同一 IR。
