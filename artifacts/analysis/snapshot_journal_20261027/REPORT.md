## API and contract

`scar.trace.snapshot_journal.SnapshotJournal(path, *, max_queue_bytes=8MiB, max_record_bytes=4MiB, max_total_bytes=1GiB, batch_bytes=64KiB, close_timeout=30.0)` uses a fresh canonical O_EXCL file. `append(row)->bool` accepts only an exact root dict of collector-owned plain snapshot data. It does **not** recursively validate or JSON-encode in the callback. CPython `marshal.dumps(..., allow_code=False)` freezes bytes synchronously before enqueueing, so it never defers a read of mutable application data. This internal API is not an arbitrary application-object serializer. `accepted_bytes`, `accepted_records`, `last_record_bytes` report accepted marshal payloads; last-record bytes is zero on rejection. These are not producer-side JSON byte-quota claims.

Frames have a versioned magic/header, one-byte kind, uint64 ordinal/length and bounded payload, followed by a closed footer. Accepted records retain append-lock FIFO order; this does not infer target causal ordering across threads. Callback-side checks are root type, C-marshalling failure, post-freeze byte/queue/total caps. Wrong root, unsupported value, record cap, total cap, queue full, writer failure and closing rejection counters remain explicit. Drops/incomplete close cannot claim complete transport. The record byte ceiling is checked after marshal allocation; callers still own their snapshot construction bounds.

The queue stores only immutable bytes. The dedicated daemon thread batches raw writes, not JSON, decoding, graph work or checksums. `is_journal_writer_thread()` uses TLS plus a pre-start weak Thread registration with identity checks in CPython's `_active` table. It covers bootstrap before the target and keeps TLS through bootstrap exit; CPython clears TLS on OS-thread exit. Constructor waits for writer readiness during installation; append never waits for queue space. Start journals before arming hooks and use this filter across all collector callbacks. No thread CPU acceleration is guaranteed.

A child after fork rejects append without acquiring inherited locks; child close discards its copied byte queue and closes only its inherited fd, without flushing or joining the parent's writer. Parent close drains/join-waits, writes footer and computes SHA by a bounded read on the **closing caller**, after hooks stop. A timeout leaves `complete=False`, no stable source SHA, and explicitly reports a possibly active writer; it is not archive eligible. The writer may still be blocked in IO, so callers must not archive it as closed. There is no fsync/crash-durability claim.

`close()` returns `{status, complete, source, counts, errors, rows_validated:false, json_byte_quota_validated:false, writer_thread_alive, writer_thread_id, writer_native_thread_id, close_sha_readback_bytes}`. A regular closed `source` is `{uri, raw_bytes, sha256, format, declared_pid, closed_footer}`; timeout/identity/hash failure can leave it None. **The expected hash is `receipt['source']['sha256']`**, not a top-level field. Closing is a transport cutoff; collectors must stop their callbacks first.

`scar.analysis.snapshot_journal.materialize_snapshot_journal(path, output_jsonl, *, expected_sha256=None, max_record_bytes=4MiB, max_total_bytes=1GiB, max_output_bytes=1GiB, max_output_line_bytes=None, max_row_nodes=1_000_000, max_row_depth=64)` runs offline. Use the close source SHA in production. It requires the exact CPython build/cache tag/marshal version, verifies framing/order/footer/counts/input stability/hash, then validates plain JSON tree types/depth/nodes/cycles/finite floats and encodes `ensure_ascii=True,separators=(',',':'),allow_nan=False` plus ASCII newline. Marshal is only temporary same-runtime transport; it is not a stable cross-version or hostile-input format.

The materializer enforces independent source/record/output/line caps. Output and its `.partial` must be fresh; even an existing empty file is not overwritten. Success is exclusively published by hard link. On producer rejection, truncation, SHA mismatch, validation or output budget failure, only the prefix `.partial` remains, with `complete=False` and `output.published=False`. Receipt fields are `source={uri,raw_bytes,sha256,format,declared_pid,closed_footer}`, `output={uri,raw_bytes,lines,sha256,published}`, plus status/errors/producer footer. `domain_schema_validated=False`: callers still need their original normal typed reader; materialization creates no proof owner or new graph authority.

Default queue bounds for five streams sum to40MiB, excluding each writer's bounded inflight batch (at most max(64KiB, one framed record)), batch-copy/freeze temporaries and the caller's already-constructed row. Close SHA readback and offline validation are separate IO/CPU costs.

## Actual checks and measurement

`RESULT.json`: owned script actual exit0 in0.9436s, peakRSS47,736KiB. It checked ten accepted rows across a mutable original row, two producer threads and fork: mutating the original after append did not change the frozen row; per-thread order held; the child rejected and never flushed a parent frame. Queue capacity rejection was counted and materialized only incomplete. NaN was accepted as storage but rejected by offline JSON validation, confirming the separation. Output-line cap, wrong expected SHA and a truncated copy never published. The small original and failure receipts are preserved. Unsupported app/dict-subclass/list-subclass/code probes all failed in marshal without invoking application repr/iter/reduce/items hooks.

`READY_CHECK.json` separately records actual `setprofile_all_threads` coverage of writer `run`, `_writer_main`, Condition wait and `_delete`; the parent remained outside writer TLS. `BOUNDARY_BEFORE.json` retains the original erroneous exact-byte-ceiling EOF refusal; `BOUNDARY_AFTER.json` records the same original closed row read successfully at that exact ceiling after `cda2bcfe`. No prior receipt was overwritten.

For **the same5,000 preconstructed rows**, one local run measured JSON with a64KiB buffer at **0.08045s**, journal append at **0.03480s**, close/drain/SHA at **0.02088s**, and offline validation/JSON at **0.71930s**. The materialized JSONL SHA is exactly the baseline SHA. Journal raw size was **4,172,887B** versus JSONL **4,794,560B**; accepted marshal payload4,086,782B, queue highwater3,976,684B, inflight highwater65,286B. This measured a shorter producer interval by moving work offline; it does **not** demonstrate threaded CPU acceleration or faster end-to-end processing (the offline phase is real additional cost), collector/LeWM speedup, low total interference, or complete modeling.

The large measurement files remain local with exact URI/SHA/size in `RETENTION.json`; Git retains only the small cases, controls, receipts and this report. No target episode, native import or model/lowerer acceptance ran here.
