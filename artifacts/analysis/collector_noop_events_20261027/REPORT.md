# Skip domain work for unconsumed C completion notifications

Base `955d3b57`; only production change is `scar/trace/call_edges.py`, in the private `install.profile` wrapper. Both ordinary `CallEdgeRecorder.profile` and `CallOperandObserver.profile` immediately ignore `c_return`/`c_exception`; the wrapper previously acquired the shared lock and called both for each notification. The new branch avoids those calls and that lock. `previous` stays at the original position, including exception propagation. `c_call` interference detection, Python entry/return locking, source witness checks and existing rows/IDs remain unchanged. No capture domain or dependency is omitted.

The actual current before/after wrapper bodies were consumed in a metadata fixture with the real domain methods, without installed hooks, Torch, native/OS collection or LeWM. Three alternating rounds of 100,000 C completion notifications measured medians **0.117470330s → 0.062885715s**. All 100,000 previous callbacks occurred in each timing; its exact KeyboardInterrupt object propagated. The normal detector still reported `VISIBLE_HOOK_OR_MONITORING_MUTATION` for the actual sys.setprofile C callable supplied to c_call. Two ordinary frame rows (1,233B) and code descriptors (559B) were byte-identical. `RESULT.json` retains source hashes and limits. This is scoped method cost, not a LeWM speedup or a claim to have profiled the full hook stack. The fixture corrected missing setup fields/alias-sensitive top-level locals before its final successful result; no production failures were reclassified.

The saved 69.248s old LeWM import-prefix diagnostic remains separate: SnapshotJournal.append **913,844 / 10.785s**, environment dispatch **62,680 / 5.088s**, code-key record **1,369,208 / 3.324s**, all inclusive and overlapping. Target fields and profile-setter scanning were subsequently fixed, so those old timings cannot establish current exclusive rankings. Snapshot append still synchronously marshals each row and takes a condition lock (`snapshot_journal.py:147–190`); freezing the dynamic fact before release remains necessary. A possible next small transport change is notifying the writer only on empty→nonempty transitions, but its contribution is unmeasured and it is not changed here.

Current-code redundancy/coverage boundaries:

- `call_operands._on_call:964–995` repeats immutable code-key/layout queries through `_shape`, targets, environment validation and pending state. A callback-local static description could be shared after each consumer independently checks the current `function.__code__ is observed_code`; no function→code association or mutable defaults/receiver/cell state may be cached. This is a separate 3-source proposal, not implemented.
- `callable_environment.dispatch:325–363` does not scan globals or cell contents. It records current namespace/cell owners and defaults/kwdefaults occurrence tokens. Those facts support environment association and cannot simply be deleted. `_resolve_global`'s full dictionary passes belong to instruction capture, not process-ports' CALL-only mask.
- `execution_evidence.py:352–354` already uses `with_stack=False, with_modules=False`. ETO/dispatch supply Tensor/schema/ports; Kineto supplies runtime/kernel/copy/allocation; Python profiling supplies frame/entry/return and environment evidence. Removing one as an assumed duplicate would lose cross-layer evidence. No saved measurement here separates native profiler cost.

No multi-GB raw scan, new LeWM run or production snapshot mutation occurred. All source changes and this report are confined to `collector-noop-events`; main index is untouched.
