# Independent source dependency workers

New production file only: `scar/analysis/source_dependency_workers.py`. The implementation depends on query commits `da9ac979` + `858c0ea7`, and native publication/reader commit `0b25465f87365932f14b08ad0696696bfce4b698` (locally cherry-picked as `091cb702`). That dependency is not reimplemented or changed by this delivery.

API: `build_source_dependency_workers(publication_path, output_dir, *, expected_manifest_sha256=None, max_workers=4, max_inflight=None, return_budget=SourceReturnBudget(max_bodies=64), max_bindings=64, max_queries=512, max_nodes=128, max_depth=32, max_routes=512, ...)`. Maximum workers is eight; inflight is at most twice the worker count. None for expected SHA first obtains an actual metadata receipt; all children are then pinned to that exact SHA. The reader's closed-shard and ordinary typed model checks remain in place.

The parent reads only publication metadata and source receipts. A spawn task contains paths, SHA, ordinal, numeric query ceilings and a plain typed-budget description. Each child rereads the normal closed publication/shard, constructs an independent `SourceDependencyBatchSession`, and writes its own bounded gzip query view and immutable terminal record. No live owner, ProgramIndex, graph or body is sent through the process pool. Parent scheduling reserves each inflight view's maximum output allowance. A failed shard retains its own failure/partial output; it is not retried. All original qualified namespaces, InvocationKeys, Uses and source/publication provenance remain referenced, with no new Run or graph IDs.
