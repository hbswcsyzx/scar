# Native and GPU model scope audit

## Observed in the retained LeWM capture

Counts below use separate provider denominators. ETO has 310,412 nodes; 190,498 rows contain schema text and 119,912 do not. Kineto reports 230,818 `cpu_op` records and 79,592 `user_annotation` records. These are independent axes: a schema-less `cpu_op` remains an operation boundary, while a `user_annotation` is evidence metadata. The evidence importer currently assigns broad provider kinds to `OperationDefinition`; `metadata.category` and `op_schema` carry the distinctions needed for modeling.

## Proposed boundary

- Model schema-declared native operations and observed `cpu_op` calls as operation boundaries even when schema, completion, values, effects, or resource bindings are unavailable. Preserve each unknown explicitly.
- Model program-controlled allocation, buffer reuse, GPU launch/copy/sync, and resource reads/writes at the highest boundary that can change an optimization decision. Attach duration, byte/shape, and resource summaries only when the source supplies them; keep the raw profiler facts on demand.
- Keep `user_annotation`, SCAR dispatch markers, import/provider validation loops, per-kernel implementation details, driver internals, and non-program allocator bookkeeping in evidence. They can qualify or explain an operation; they are not target-program operations.
- Share source, schema, and resource catalogs by their existing artifact/definition IDs. Reuse `OperationDefinition`, `OperationInstance`, `Operation`, `Value`, `Use`, `Region`, and execution records where their producer, consumer, and containment facts exist. Do not create a `ProgramSnapshot` or normal/raise route to accommodate an unqualified observation.

## Experimental adapter audit

`scar/trace/native_schema_graph.py` is an uncommitted experiment, not a merged graph authority. Its 0–128 original ETO ordinal slice completed the typed codec round trip and queried back through an existing `OperationInstanceID`. It produced 59 schema-text rows, 24 schema-less `cpu_op` rows, 44 `user_annotation` rows, one other boundary, 246 input ports, and 59 output ports. The prototype retained no Tensor payloads and left outcome, effects, alias, value identity, readiness, state, and resource status unknown.

The prototype demonstrates a path to the missing boxed scalar/container port view, but it duplicates operation labels, parent/category data, and schema text already represented by the evidence instance and definition/contract. It also emits a typed row for each annotation. Proposed convergence is a port-only observation adapter keyed by existing `OperationInstanceID`, resolving schema and parent through existing `OperationDefinition`/`OperationInstance` records. Annotation rows remain in evidence and do not become program operations. The output is not a substitute for canonical `Operation`/`Use` or execution provenance.

The compact actual readback summary is in [`native_schema_range_0_128_summary.json`](native_schema_range_0_128_summary.json). The retained source and native evidence partitions were read-only; no LeWM workload or long import was rerun.
