# Snapshot postprocessing → original OS provenance

Implemented one independent consumer module on main `1d4d681d`: `scar/analysis/os_postprocessing_roles.py`. Main, its frozen collector and the running LeWM were not changed. No capture, target, OS reimport, graph build or full LeWM scan was run.

`bind_snapshot_postprocessor_roles(coordinates, fragment, receipt_artifacts)` consumes the normal same-Run `CaptureCoordinates` and `OSResourceFragment(interface_work=True)`, plus exact `ProviderArtifact` receipts. It preserves the original Run/ProcessInstance IDs and all OS facts. It reuses the normal parent's birth fact, checks the child's independent coordinate birth anchor, rejects ambiguous/reused PID births and `CLONE_THREAD`, and reads/hash-checks only candidate worker OS files for original exec argv. The exact module, journal SHA, journal/output/receipt URIs must agree. Archive aliases require the coordinate binder's explicit original/local mapping.

The returned view supports `query(original_provider_fact, process=original_ProcessInstanceID)`. A positive result is only `SCAR_OFFLINE_POSTPROCESSING`/`POSTPROCESSING` navigation with original declaration/birth/exec facts. The interval starts at the successful exec record and stops at the next exec/exit, unparsed provider boundary, or retained EOF in that same original file. EOF is not process termination, and queries cannot qualify lines beyond the retained artifact. Pre-exec work, other threads/descendants and missing proofs stay unclassified; no default APPLICATION/RECORDING label is invented. Failed conversion remains postprocessing when its declaration and exact exec match; materialization success and publication are separate recorded fields.

Defaults: 32 receipts, aggregate metadata 4MB, selected worker OS decoded 64MB, line 64KB. No parent OS file is reread. Existing normal parsing and coordinate membership must already establish the parent's/child's incarnations; incomplete birth parsing produces an explicit frontier, not a guessed child.

Syntax/import, one argv component check (including another-module rejection), and empty-query behavior passed. **No positive same-Run role has yet been runtime-verified.** Consume the new LeWM's actual closed worker receipts and ordinary OS fragment once available; the small previous snapshot example had no matching OS provenance and is not promoted. This is a receipt/provenance bridge, not a new OS/FD model or source/image proof.
