# Query-granularity dependency views

One production file changed: `scar/analysis/source_dependency_workers.py`, based on main `75ee9dcf`. The new optional arguments are `view_layout='single'|'queries'` (default `single`) and `shard_indices=None|tuple[int,...]`. Old single mode retains its original JSON/gzip layout and byte caps. No body graph, dependency algorithm, model schema, collector, CLI or existing receipt was changed.

In queries mode each existing query row (`kind`, binding/argument selector and `view`) is stored unchanged as an individual canonical gzip JSON file. The small `query-index.json` contains `batch_header` (the original batch's non-query fields) and `queries[]` (ordinal, selector and gzip receipt). Its worker `output` identifies `view_layout='queries'`, plain canonical index representation and query payload totals. This changes storage granularity, not the query language or IR. No endpoint/Run/Invocation/Use identities are reconstructed.

The original **64 MB decoded cap now applies to each query**, and the original **64 MB stored cap covers the entire shard**, including all gzip files, query index and worker start/terminal metadata. Metadata is reserved inside that cap; no byte limit was increased. A failing query retains a partial index with exact ordinal/selector and failure. The parent index explicitly lists selected ordinals and unselected candidate scopes as `NOT_SELECTED_THIS_RUN`; it never borrows their old success as a new proof.
